# Silai Saathi Backend

This folder is the complete Node.js/Express API for Silai Saathi. The API is
written in TypeScript and compiled to `dist/` for production. It is
self-contained and can be deployed to a VPS without copying the mobile app or
the repository root.

## What is in this folder

| Path | Purpose |
| --- | --- |
| `src/server.ts` | Starts the HTTP server and connects to PostgreSQL |
| `src/app.ts` | Express app, CORS, security headers, rate limits, `/health` |
| `src/config.ts` | Environment configuration and validation |
| `src/db.ts` | PostgreSQL connection pool |
| `src/types.ts` | Shared API response and database row types |
| `src/middleware/` | JWT authentication and role checks |
| `src/routes/` | Authentication, admin, and manager API endpoints |
| `src/scripts/setup-db.ts` | Applies `schema.sql` and creates the first admin/operations |
| `src/utils/` | Validation, serializers, SQL helpers |
| `supabase/schema.sql` | Full database schema |
| `supabase/seed.sql` | Optional sample admin, managers, employees, operations |
| `tsconfig.json` | TypeScript compiler configuration |
| `.env.example` | Environment variable template |
| `ecosystem.config.cjs` | PM2 production process configuration |
| `deploy/nginx.conf.example` | Reverse-proxy example |

`dist/` is generated by `npm run build` and is not committed.

All application data reads and writes go through the Express API. The mobile
app never connects directly to PostgreSQL.

## Local development

```powershell
cd backend
npm install
Copy-Item .env.example .env
```

Fill in `DATABASE_URL` and `JWT_SECRET` in `.env`, then:

```powershell
npm run db:setup
npm run dev
```

`npm run dev` uses `tsx` and reloads the API when a TypeScript file changes. To
run the compiled version locally:

```powershell
npm run build
npm start
```

`npm run db:setup` only creates the admin account and starter operations. To
create the sample 10 managers and 20 employees, run `supabase/seed.sql` in the
Supabase SQL Editor instead.

Check the API:

```text
http://localhost:4000/health
```

## Production environment

Set these values in `backend/.env` on the VPS:

```dotenv
NODE_ENV=production
HOST=0.0.0.0
PORT=4000

DATABASE_URL=postgresql://postgres.PROJECT_REF:PASSWORD@aws-0-REGION.pooler.supabase.com:5432/postgres
DATABASE_SSL=true
DATABASE_SSL_STRICT=false

JWT_SECRET=replace-with-a-long-random-secret
JWT_EXPIRES_IN=7d
CORS_ORIGIN=https://your-web-app.example.com

ADMIN_USERNAME=admin
ADMIN_NAME=Administrator
ADMIN_PASSWORD=change-this-before-running-setup
```

Notes:

- Use the Supabase **Session pooler** URL when the VPS does not support IPv6.
- Generate `JWT_SECRET` with `openssl rand -hex 48`.
- `CORS_ORIGIN` only matters for a web client. Use comma-separated exact origins;
  do not use `*` in production if you serve a browser app.
- `ADMIN_USERNAME` and `ADMIN_PASSWORD` are used only by `npm run db:setup`.
- Never put `DATABASE_URL`, `JWT_SECRET`, or Supabase keys in the mobile app.

## Deploy on an Ubuntu VPS

The examples below use `/var/www/silai-saathi-backend` and
`api.example.com`. Replace them with your own paths and domain.

### 1. Install Node.js and PM2

```bash
sudo apt update
sudo apt install -y nginx
curl -fsSL https://deb.nodesource.com/setup_20.x | sudo -E bash -
sudo apt install -y nodejs
sudo npm install -g pm2
node --version
```

Use Node.js 20 or newer.

### 2. Upload only the backend folder

Use Git, `scp`, or `rsync` to copy the **contents of `backend/`** to the VPS:

```bash
sudo mkdir -p /var/www/silai-saathi-backend
sudo chown -R "$USER":"$USER" /var/www/silai-saathi-backend
```

From your development machine:

```powershell
scp -r backend\* user@YOUR_VPS_IP:/var/www/silai-saathi-backend/
```

Do not upload `node_modules`, `dist`, or the local `.env`. Install dependencies
on the VPS, build there, and create a production `.env` there.

### 3. Install dependencies, build, and configure

```bash
cd /var/www/silai-saathi-backend
npm ci
cp .env.example .env
nano .env
chmod 600 .env
npm run build
npm prune --omit=dev
```

`npm ci` installs the TypeScript compiler as a development dependency. The API
is built into `dist/`, then development packages are removed from the server.

### 4. Prepare the database

Run `supabase/schema.sql` and then `supabase/seed.sql` in the Supabase SQL
Editor, or run the compiled setup script:

```bash
npm run db:setup:prod
```

This runs `dist/scripts/setup-db.js` and does not require TypeScript to remain
installed. Remember: setup creates only the admin and starter operations. The
full sample data with 10 managers and 20 employees comes from `seed.sql`.

### 5. Start with PM2

```bash
pm2 start ecosystem.config.cjs
pm2 save
pm2 startup
```

Run the command printed by `pm2 startup` once, then check:

```bash
pm2 status
pm2 logs silai-saathi-api
curl http://127.0.0.1:4000/health
```

Expected health response:

```json
{"status":"ok","database":"connected"}
```

### 6. Put Nginx and HTTPS in front

Copy the example configuration:

```bash
sudo cp deploy/nginx.conf.example /etc/nginx/sites-available/silai-saathi
sudo ln -s /etc/nginx/sites-available/silai-saathi /etc/nginx/sites-enabled/silai-saathi
sudo nano /etc/nginx/sites-available/silai-saathi
```

Change `api.example.com` to your API domain, point that domain's DNS record to
the VPS, then:

```bash
sudo nginx -t
sudo systemctl reload nginx
sudo apt install -y certbot python3-certbot-nginx
sudo certbot --nginx -d api.example.com
```

Allow only SSH and Nginx through the firewall:

```bash
sudo ufw allow OpenSSH
sudo ufw allow 'Nginx Full'
sudo ufw enable
```

Do not expose PostgreSQL or the internal Node port to the public internet.

### 7. Point the mobile app at the API

In `mobile/.env`, or in the EAS build environment, set:

```dotenv
EXPO_PUBLIC_API_URL=https://api.example.com
```

Rebuild or restart the Expo app after changing this value.

## Updating the deployment

From the VPS:

```bash
cd /var/www/silai-saathi-backend
npm ci
npm run build
npm prune --omit=dev
pm2 reload silai-saathi-api --update-env
pm2 logs silai-saathi-api --lines 50
```

If a database change is required, apply the relevant SQL file in Supabase or run
`npm run db:setup:prod` before reloading the API.

## API routes

| Method | Route | Access |
| --- | --- | --- |
| `GET` | `/health` | Public |
| `POST` | `/auth/admin/login` | Public |
| `POST` | `/auth/manager/login` | Public |
| `GET` | `/auth/me` | Signed-in user |
| `GET` | `/admin/dashboard` | Admin |
| `GET/POST/PATCH` | `/admin/managers` | Admin |
| `GET/POST/PATCH` | `/admin/employees` | Admin |
| `GET/POST/PATCH` | `/admin/operations` | Admin |
| `GET` | `/admin/entries` | Admin |
| `GET` | `/manager/home` | Manager |
| `GET` | `/manager/entries` | Manager |
| `POST` | `/manager/entries` | Manager |

Passwords are hashed with bcrypt. Protected routes require a JWT bearer token
and re-check that the account is still active on every request.
